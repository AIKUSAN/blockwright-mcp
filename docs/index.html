Cubes

place_cube

stable destructive

Place Cube

Creates cubes in one reversible edit. Texture and group are optional, allowing untextured blockouts. Explicit face targets never use the current UV selection; partial/custom faces require per-face UV support. Elements accept inflate, plus uv_offset and mirror_uv for box UV cubes; unknown element fields are rejected. Cubes the format's size limiter rejects (for example Java Block elements outside -16…32) are refused and nothing is created, unless Blockbench's Deactivate Size Limit setting is on.

Name Type Required Description
elements object[] required Array of cubes to place, with optional Java shading fields. [minItems: 1]
texture string optional Texture UUID, ID or name. When omitted, uses the default texture if one exists; otherwise creates untextured cubes.
group string optional Parent group UUID or unique name, or root (default). Missing or ambiguous names are rejected.
faces "north" | "south" | "east" | "west" | "up" | "down"[] | unknown | boolean | object[] optional true applies texture to all faces with Auto UV; false skips texture assignment. Named faces use Auto UV; false/custom rectangles disable Auto UV outside Hytale. Hytale always retains Auto UV 1 and custom rectangles must match the geometry's face dimensions. Partial/custom faces require per-face UV support. Single-texture formats may still display the project texture. (default: true)
side_check "warn" | "refuse" | "off" optional Compare left/right names with where the part sits (the model faces -Z, so its right is +X). warn: create and report mismatches; refuse: create nothing if any name disagrees; off: skip. (default: "warn")

modify_cube

stable destructive

Modify Cube

Modifies the cube with the given ID. Auto UV setting: saved as an integer, where 0 means disabled, 1 means enabled, and 2 means relative auto UV (cube position affects UV). A new from/to/inflate that the format's size limiter rejects (for example Java Block elements outside -16…32) is refused before anything changes, unless Blockbench's Deactivate Size Limit setting is on.

Name Type Required Description
id string optional ID or name of the cube to modify. Defaults to selected, which could be more than one.
name string optional New name of the cube.
origin number[] optional Pivot point of the cube. [minItems: 3, maxItems: 3]
from number[] optional Starting point of the cube. [minItems: 3, maxItems: 3]
to number[] optional Ending point of the cube. [minItems: 3, maxItems: 3]
rotation number[] optional Rotation of the cube. [minItems: 3, maxItems: 3]
autouv "0" | "1" | "2" optional Auto UV setting. 0 = disabled, 1 = enabled, 2 = relative auto UV.
uv_offset number[] optional UV offset for the texture. [minItems: 2, maxItems: 2]
mirror_uv boolean optional Whether to mirror the UVs.
shade boolean optional Whether to apply shading to the cube. Java 26.3+ projects ignore this flag; shade=false is mapped to shade_direction_override 'up' there, matching Blockbench's own import.
shade_direction_override "" | "north" | "south" | "west" | "east" | "up" | "down" optional Java Edition 26.3+ shade direction override: the face direction whose lighting shade is applied to every face. '' removes the override. Replaces the boolean shade flag in formats with java_cube_shade_direction_override (new Java Block projects default to 26.3).
light_emission integer optional Block light emitted by the cube (0-15). Exported by Java Block formats. [min: 0, max: 15]
inflate number optional Inflation amount for the cube.
color number optional Single digit to represent a color from a palette.
visibility boolean optional Whether the cube is visible or not.

knife_cut_cube

experimental destructive

Knife Cut Cube

Headless Blockbench Knife tool for cubes: splits each target cube with planes perpendicular to one axis at the given positions, keeping each piece's share of the face UVs. The original cube keeps the lowest piece; new pieces get unique names. One undo entry covers every cut and the selection is left unchanged.

Name Type Required Description
cubes string[] optional Cube UUIDs or unique names to cut. Defaults to the selected cubes. [minItems: 1]
axis "x" | "y" | "z" required Axis the cut plane is perpendicular to.
positions number[] required Cut-plane coordinates along the axis, in the cube's from/to space (model space for unrotated cubes). Positions closer than the cube's inflate to its from/to edges, or outside it, are skipped for that cube and reported sorted and deduplicated. [minItems: 1]

slice_cubes_to_block_grid

experimental destructive

Slice Cubes To Block Grid

Cuts cubes wherever they cross a Bedrock block boundary (16-unit grid, x/z centered) and, by default, regroups the pieces into one group per block cell pivoted at that block's origin. Use it to divide an oversized custom block model into per-block sections that each fit Bedrock's 30×30×30 limit. Rotated cubes are left uncut on the affected axes and reported.

Name Type Required Description
cubes string[] optional Cube UUIDs or unique names to slice. Defaults to every cube in the project. [minItems: 1]
axes "x" | "y" | "z"[] optional Axes to slice along. Cubes rotated (or inside groups rotated) about the other two axes are skipped on that axis, as Blockbench's own slicer does. (default: ["x","y","z"]) [minItems: 1]
cell_size number optional Block size in model units; 16 for Bedrock. Horizontal boundaries sit at ±half a cell, vertical ones at multiples. (default: 16)
regroup boolean optional Move every resulting cube into a group named after its block cell (bottom, top, right_top_front, top2, …) pivoted at that block's origin, so each group is one exportable block section. Pieces leave their previous bone; the report lists each source cube's former group. (default: true)
parent string optional Parent group UUID or name for the cell groups; must not be rotated. Defaults to the project root.
group_prefix string optional Prefix for cell group names, e.g. `goal_` yields `goal_top`. Existing groups are reused only when their name and block-origin pivot match; otherwise a numbered name is chosen. (default: "")

inspect_block_bounds

experimental read-only

Inspect Block Bounds

Reports cube, group, and whole-model extents against Blockbench's Bedrock block limit (a 30×30×30 box whose center may sit up to 7 units from the block center), the block cell each cube occupies, and the grid cut positions slice_cubes_to_block_grid would use. Read-only. Extents ignore rotation; rotated cubes are flagged.

Name Type Required Description
cubes string[] optional Cube UUIDs or unique names to inspect. Defaults to every cube in the project. [minItems: 1]
cell_size number optional Block size in model units; 16 for Bedrock. (default: 16)
max_size number optional Maximum geometry size per axis for one block (Bedrock: 30). (default: 30)
max_center_offset number optional How far the limit box may shift from the block center per axis (Bedrock: 7, giving x/z within ±22 and y within -14…30). (default: 7) [min: 0]

get_guide

experimental

get guide

Return a playbook. Pass `topic`: 'modeling' (default — proportions, detail, rotation), 'detailing' (the cube budgets and the 4-layer doctrine that stop models coming out as 15 boxes — read it before building anything with a costume, armour or cloth), 'orientation' (which side is the model's LEFT — read before anything with a left and a right), 'rigging' (bone hierarchy, joint origins, why 2-bone limbs animate like cardboard), 'texturing' (the smooth @volmur/Hytale look), 'vfx' (pixelated flames/energy/projectiles), 'animation' (axis signs, gaits, easing, the measure-then-review loop), 'review' (how to get the user to confirm work instead of declaring it good yourself), 'reference' (how to ACTUALLY match a reference image, find more references on the web and build the palette), 'character' (anime/stylised characters: proportions, face, hair, cloth, the generator recipe), 'mechanism' (gears, pistons, pipes and animating them) or 'inspection' (how to find and fix the small things screenshots miss). READ the relevant topic BEFORE building/rigging/texturing/animating — it dramatically improves results.

get_orientation

experimental

get orientation

THE left/right authority for this model — call it before rigging, mirroring, attaching an item to a hand, or interpreting any render. Returns which way the model faces and which world axis is the model's OWN right and left (Minecraft models face -Z, so the model's right is +X), plus the trap that causes most mistakes: a front-view render shows the model MIRRORED (its right hand appears on the LEFT of the image), exactly like facing a person. Also returns the rotation-sign cheat sheet (+X swings a hanging limb FORWARD, tips an upright torso BACKWARD; +Y turns the model to its own left).

request_review

experimental

request review

SHOW THE USER and WAIT for their verdict — the honest alternative to looking at your own screenshot and declaring it good. Renders labelled views (or animation poses) and posts them as a card in the MCP Copilot panel inside Blockbench, then waits a SHORT window for the user to press 'Looks right' / 'Needs changes' and optionally type a comment. If they haven't answered yet it returns `pending: true` with a `review_id` — the card stays open, so call wait_review with that id to keep waiting (that loop is how a minutes-long human review fits inside an MCP client's per-request timeout). Call it after every user-visible milestone: the blockout, the texture pass, EACH animation, anything the user asked for specifically, and before you claim a task is finished. Run the objective checks (check_model / check_sides / check_rig / analyze_animation) FIRST — don't spend the user's attention on something a tool would have caught. If the answer is 'needs changes', fix exactly what they said and ask again. `pending` and a timeout are NOT approval.

Name Type Required Description
question string required One concrete question, naming what to look at. e.g. 'Walk cycle: is the stride right and do the knees bend enough?'
title string optional Short header for the panel card.
details string optional What you changed since the last review, and anything you are unsure about.
views string[] optional Camera views to render, named from the MODEL's point of view: 'front' (its face), 'back', 'left'/'right' (the side its left/right arm is on), 'front_right', 'top'. Default front_right/front/left/back.
animation string optional Animation name/uuid to review — renders poses from it instead of the rest pose.
times number[] optional Times (seconds) to sample when `animation` is set. Default 0/25/50/75%.
options string[] optional Custom answer buttons instead of approve/reject (e.g. ['Left hand','Right hand']).
wait_seconds number optional How long THIS call waits before returning `pending` (default 25). Keep it under your client's request timeout; use wait_review to keep waiting.
timeout_seconds number optional How long the card stays open in Blockbench (default 900, max 3600).

wait_review

experimental

wait review

Keep waiting for a review the user hasn't answered yet — call this in a loop after request_review/ask_user returns `pending: true`, passing the `review_id` it gave you. make_palette

experimental

make palette

Build the model's COLOUR PALETTE and store it on the project, so texturing uses real colours instead of guessed hex codes. Three ways: (1) from a reference/concept image (default when one is loaded): background removed, light and shadow of the same material merged into one family, each family returned with a 5-step hue-shifted ramp [deep shadow, shadow, BASE, light, highlight]; (2) from `regions` — point at parts of the reference ({name:'hair', x:0.5, y:0.1} or rect) and each becomes a named entry; (3) from a TEXT brief — `colors` you name ({hair:'#5a6fd0', coat:'navy'}), or a harmony from `base_color`/`hue` + `scheme` + `mood`. Afterwards detail_cubes rules can use color:'$hair', '$hair.shadow', '$hair.light', '$hair.highlight', '$hair.deep'. Returns a swatch card image. Do this right after loading references, and for text-only tasks before texturing.

compare_reference

experimental

compare reference

THE reference-matching tool — turns 'does it match?' into a measured number so you stop building blind. Renders your model from the chosen angle on a transparent background, extracts the model + reference SILHOUETTES, normalises them (so scale/position in the viewport don't matter) and returns: match_percent (silhouette IoU 0-100), aspect_delta_pct (model too wide/narrow), ref_only_pct (reference area with NO model under it = MISSING mass), model_only_pct (model beyond the reference = EXTRA mass), a verdict + concrete advice, AND a composite image [reference | your model | overlay]. In the overlay RED = reference-only (add mass there), BLUE = model-only (trim), WHITE = match. Aim the camera to the reference angle first (set_camera_angle/screenshot_views) or pass `view`. Call this EVERY modeling pass and iterate until match_percent >= 85 — do not declare a match by eye.

Name Type Required Description
reference string optional Reference id/name/index to compare against (default: the most recent).
view string optional Camera preset to render from ('front','back','left','right','isometric_right_front',...). Omit to use the current view (aim it first). Models usually face -Z, so 'back' shows the creature's face.
position number[] optional Explicit camera position [x,y,z] (overrides view). [minItems: 3, maxItems: 3]
target number[] optional Explicit look-at target [x,y,z]. [minItems: 3, maxItems: 3]
threshold number optional Alpha cutoff 0..1 for the model silhouette (default 0.45).
